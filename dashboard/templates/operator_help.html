How to use this page
{% if operator_help_key == "watchlist" %}

What this does: A Watch saves what City Manager OS should look for and who should receive a Notification when it finds a Match.

Set up a Watch in five steps:

  1. Choose what to watch for.
  2. Choose a Location and Distance when needed.
  3. Choose the Recipient.
  4. Send an isolated Test Notification.
  5. Turn the Watch on.

Examples: Watch within one mile of Town Hall, watch for “water main,” or watch for “road closure” within one mile of a selected street.

Safe change: Pausing stops future Matches. It does not delete stored alerts or Notification history.

{% elif operator_help_key == "subscribers" %}

What this does: Manages Recipients: the people or notification channels that may receive City Manager OS Notifications.

Use it for:

  • Adding an authorized Recipient.
  • Changing an existing Notification channel.
  • Temporarily pausing a Recipient without deleting the record.

Important: A Recipient receives only the Notifications produced by Watches connected to it.

Safe change: Pausing a Recipient affects future Notifications only. It does not remove alert or Notification history.

{% elif operator_help_key == "routines" %}

What this does: Creates repeatable municipal work such as inspections, checks, assignments and recurring operational responsibilities.

Use it for:

  • Daily or weekly work.
  • Recurring inspections and checklists.
  • Work that needs an owner and verification.

Remember: Generated actionable work uses the existing Command Center / issue system. This is not a separate task database.

Safe change: Pausing a routine stops new occurrences. Existing generated work remains available for completion and verification.

{% elif operator_help_key == "schedule" %}

What this does: Manages Township meetings, events and preparation context.

Use it for:

  • Meetings requiring preparation or decisions.
  • Township events and outside-agency events you are managing.
  • Tracking confirmation, attendees, waiting items and preparation.

Create Action should be used when the event requires real accountable work. That action becomes a Command Center issue.

Safe change: Updating event details does not create a separate task unless you explicitly create an action/follow-up.

{% elif operator_help_key == "integrations" %}

What this does: Manages external data sources feeding City Manager OS.

Status: LIVE means active and healthy. PAUSED means collection is intentionally off. NEEDS SETUP means required configuration or credentials are missing. ERROR means the latest source operation failed.

Use TEST first: Test a connector before activating it whenever possible. Activation enables scheduled collection.

Examples: NJ TRANSIT, PATH, weather, outages and event feeds.

Safe change: Pause a questionable source rather than deleting it. Source health and prior run history remain available for diagnosis.

{% elif operator_help_key == "source_health" %}

What this does: Shows whether City Manager OS sources are successfully providing data.

Look for:

  • Current health status.
  • Last successful update.
  • Recent errors or stale sources.

Use this page when: Information seems missing, stale or a source appears to have stopped updating.

Safe page: This is primarily diagnostic. Viewing source health does not alter operational data.

{% elif operator_help_key == "deliveries" %}

What this does: Shows the audit trail of Notification attempts.

Use it to answer:

  • Was an alert actually sent?
  • Which Recipient received it?
  • Was it held as a repeat, or did delivery have a problem?

Important: This page is Notification history. Use Watches or Recipients to change what happens next.

Safe page: Reviewing delivery records does not resend or modify alerts.

{% else %}

What this does: Administrative controls for this City Manager OS module.

Review the current configuration before making changes. When unsure, pause rather than delete.

{% endif %}
